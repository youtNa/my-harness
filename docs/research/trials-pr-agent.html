Qodo PR-Agent 实际试用报告

日期：2026-11-19　实验：E001 local agent quality loop

1. 目标

验证开源 PR-Agent 是否能够在个人可控环境中安装、提供可调用入口，并判断它能否在没有模型凭证时完成真实 PR Review。

2. 实际环境

项目结果
主机macOS，Python 3.10.10，Node.js 24.16.0
DockerDocker 29.2.1。Docker Desktop 在实验过程中启动成功。
测试镜像python:3.12-slim
PR-Agent 包PyPI 可见版本为 0.50.0，并列出历史版本。
GitHub 源码克隆主机侧因 DNS 无法解析 github.com 失败，未把源码假设为已获取。

3. 已实际执行的步骤

  1. 确认 Docker Desktop 可启动，docker info 返回 Server Version 29.2.1。
  2. 在临时 Python 容器中执行 pip index versions pr-agent，确认 PyPI 可访问，并观察到最新列出的版本为 0.50.0。
  3. 尝试从官方 GitHub 仓库克隆源码。该步骤实际失败，错误为 Could not resolve host: github.com。
  4. 尝试在临时容器中安装 pr-agent==0.50.0 并调用 CLI。安装过程超过单次试验时间窗口，未取得可采信的 CLI 输出，因此不把“CLI 可用”记为成功。

4. 凭证和能力边界

本次没有使用任何 GitHub Token、OpenAI Key、Anthropic Key 或其他模型凭证，也没有伪造 PR Review 结果。

能力本次结论
安装包元数据可从 PyPI 查询到版本信息。
源码安装被当前主机 DNS/网络阻断，未完成。
CLI 帮助和本地入口未获得足够稳定的安装完成结果，待后续重试。
真实 PR Review未执行。需要模型 API Key、仓库/PR 输入以及对应 GitHub 权限。
GitHub Action未执行。需要 GitHub Actions 环境和模型凭证，且应使用实验仓库。

5. 对产品方向的判断

  • PR-Agent 的个人试用门槛低于 AgentCore，不需要 AWS 企业账号。
  • 它适合作为“独立 PR Review 层”进行验证，而不是完整的 Issue 到 PR 开发团队。
  • 真实价值必须通过已知缺陷、隐藏回归测试和人工基准对比来验证，不能以 Review 评论数量作为质量指标。
  • 在没有模型凭证时，只能验证安装、配置和执行入口，不能声称已经验证了 Review 质量。

7. 清理记录

所有安装尝试使用临时 Docker 容器，没有写入主机 Python 环境，也没有保存凭证。源码克隆失败，没有残留有效源码副本。后续若产生 Docker 容器或卷，应在实验结束后执行 docker rm 和 docker volume rm，并把清理结果写入本报告。
